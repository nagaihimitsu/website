# TXTで記録を増やす

普段編集するのは `public/data/` の9個のTXTと `public/photos/` の写真だけです。UTF-8で保存してください。BOMあり・なし、LF・CRLF、行頭の `#` コメント、空行に対応します。

## 実績（5ファイル）

| TXT | 入力 |
|---|---|
| 訪問した国.txt | 日本、アメリカ、イギリスなどの国・地域名 |
| 訪問した都道府県.txt | 東京都、埼玉県など（東京、埼玉も可） |
| 登頂した百名山.txt | 富士山、穂高岳など（奥穂高岳も可） |
| ポケモン_通常色.txt | 全国図鑑番号または日本語名 |
| ポケモン_色違い.txt | 全国図鑑番号または日本語名 |

1行1項目を推奨。`日本,アメリカ,イギリス` のようなカンマ区切りも可。同じ項目の別名も同一IDに正規化し、重複は警告して1件として扱います。実績の各分類は独立し、登頂だけで県の訪問を追加したり、色違いだけで通常色を捕獲扱いにしたりしません。

国・山・県の正式名称と別名は `src/catalogs/` の各JSONを参照できます。百名山でない山は登録できません。例えば燕岳はエラーになります。

## 日付・写真（4ファイル）

`記録_国.txt` / `記録_都道府県.txt` / `記録_百名山.txt`:

```txt
# 名前|年月日|写真（public/photos/ からの相対パス）
日本|2024-05|countries/japan/01.webp,countries/japan/02.webp
日本|2025-04-02|
日本||
```

`記録_ポケモン.txt`:

```txt
# 名前または番号|normal または shiny|年月日|写真
25|normal|2024|
25|shiny|2025-08|pokemon/025_shiny.webp
```

上記は書式説明用の例です。架空の内容は本番TXTに同梱していません。写真を記載する場合は、実在する公開可能な写真を先に配置してください。

- 詳細の項目は実績TXTにも必要です。ポケモンでは該当する色の実績が必要です。
- 日付は空欄・`YYYY`・`YYYY-MM`・`YYYY-MM-DD`。年や年月だけならその精度で表示し、月日を補いません。
- 1行が1回の記録。同日でも複数行を保持。新しい日付順、日付なしは末尾です。同じ日付では元の行順。
- 写真なしなら最後の `|` を残します。両方なしは `名前||`。
- 写真はJPG/JPEG・PNG・WebP・AVIF。先頭 `/`、`..`、外部URL、バックスラッシュ、URLエンコード、`|`、カンマを含むファイル名は不可。
- 写真の順序はカンマで書いた順。左右ボタンで切り替え、クリックで拡大できます。代表写真は最新の写真付き記録の1枚目。
- 詳細がなくても実績だけで正常に表示されます。

## 写真の準備

```bash
npm run photos -- /公開前の原本/写真.jpg public/photos/countries/japan/01.webp
```

向きを補正し、縦横最大1920px、WebP品質84に変換。EXIF等のメタデータは引き継ぎません。原本は変更せず、既存の出力写真も上書きしません。

## 確認して更新

```bash
npm run validate:data
npm run test
npm run build
```

エラーは `ファイル名:行番号` と候補・修正理由を出します。未知名、不正な日付、実績と詳細の不整合、危険なパス、欠損写真はビルドを止めます。重複は警告です。空データは正常です。

TXT・写真をGitへ反映して再公開すると、自動的に件数・地図・図鑑・詳細に反映されます。開発中にTXTを変えた場合はページを再読み込みしてください。ブラウザ上の編集・保存機能はありません。
