# Codex実装指示：Suno楽曲「最終のヒット 2」のMIDI譜面取り込み

## 目的

既存のスマートフォン向けベースリズムゲームに、Suno楽曲から生成したMIDI譜面を取り込む。元の曲を再生し、その**再生位置に同期して**ノーツを表示・判定できるようにする。

**既存のクマ型キャラクター・3Dモデル・アニメーション・背景・縦画面の指板UI・音声再生エンジンを原則変更しない。** まずプロジェクトの既存の譜面モデル／ノーツ判定／再生時計／ファイル読み込み方式を調べ、拡張として追加すること。重複する新しい仕組みを作らない。

## 添付データ

- `01_midi_all_notes.json`：**元MIDIを忠実に変換**した全648ノーツ。各音の開始時刻（秒）、長さ（秒）、MIDI音高番号、音名、ベロシティ、元トラック番号などを保持する。マスターデータとして保管する。
- `02_bass_4string_candidates.json`：4弦ベース（E1/A1/D2/G2、24フレット）で出せる音だけを抽出した**557音の仮譜面**。各音に弦・フレットの候補を付与。手元のTABや原曲で未検証なので、無条件に正解譜面とみなさない。
- `03_conversion_report.json`：件数・音域・テンポメタ情報・注意点。
- `midi_to_chart.py`（同梱）：今後別のSuno曲にも使用できるMIDI→JSON変換スクリプト。

## データの意味（重要）

- `timeSec`：MIDI開始を0秒とした**絶対時刻**。最初の音は約0.789583秒。先頭の無音を削ったり、最初の音が0秒になるように全体をずらしたりしない。
- `durationSec`：音の保持時間。`velocity`：MIDI発音ベロシティ（0〜127）。
- `midiNote`：MIDI音高。例：52 = E3。`stringNumber`：1=G弦、2=D弦、3=A弦、4=E弦。`fret`：0が開放弦。
- `possiblePositions`：同じ音高を出せる弦・フレットの候補。
- `positionVerified=false`：現在の弦・フレットは**最低フレットを選ぶ簡易推定**であり、実演奏の運指ではない。
- `technique=null`：奏法は未判定。**通常弾き確定ではない。** スラップ、ポップ、ハンマリング、プリング、ゴーストノート、ミュートをMIDIの音高やベロシティだけから確定しない。
- `audioOffsetSec=0.0`：同期調整の初期値。原曲とMIDIの時刻同期は未検証。`audioSyncVerified=false`。

## 実装要件

1. `01_midi_all_notes.json` を原本とし、編集可能なゲーム譜面として `02_bass_4string_candidates.json` を取り込めるようにする。JSONのバージョンを検査し、既存の譜面ファイル形式がある場合は変換アダプターを作る。
2. 音声クロック（再生位置、再生開始／一時停止／シークの状態）を**唯一の判定時刻の基準**とする。ブラウザ等なら `audio.currentTime`、ゲームエンジンなら既存の高精度な音声再生クロックを用いる。フレーム数や独立した経過時間タイマーによってズレを蓄積させない。
3. ノーツの目標時刻は `note.timeSec + audioOffsetSec` と定義する。オフセットは曲単位で手動調整可能にする（プラスでノーツを遅らせる）。正確なオフセットは原曲音源との聞き比べで決める。
4. 曲の長さは約59.596875秒。MIDI内テンポの120 BPMは**メタ情報**として保持するが、音符時刻は `timeSec` を使用し、120 BPMを元に再計算してはいけない。
5. ノーツ描画と入力判定は取り込みデータを使用する。弦・フレットに応じたタッチ位置を対応させる。`technique=null` のノーツは通常ノーツの仮表示として扱うが、内部データ上は奏法不明のまま保持する。
6. **同時刻に複数ノーツ**が存在する。現行ゲームが和音／多点タッチに対応していない場合は、勝手に時間をずらさず、開発用にモノフォニック譜面を生成できるオプションを用意する。その際、間引いた音は別ファイルにして原本に触れない。
7. 弦・フレット候補を手動修正でき、修正が保存される仕組みにする。可能なら音高の一致する別ポジションだけを提案して手動選択できるようにする。
8. 原曲の音声ファイルはまだ同梱していない。既存ゲームへの取り込み時に曲ファイルを設定できるようにし、音源がないときは譜面読み込み・ダミー再生位置シミュレーションによる検証に限定する。
9. 画面レイアウトを崩さず、パース・再生同期・同時刻ノーツ・停止／再開／シーク・弦とフレットの適合チェックのテストを追加する。

## 現段階の解析結果と限界

| 指標 | 値 |
|---|---:|
| 楽曲長 | 59.596875 秒 |
| 元ノーツ数 | 648 |
| 標準4弦・24フレット内の候補 | 557 |
| 音域外などの除外 | 91 |
| 元MIDI音域 | E1〜D#6 |
| MIDIトラックの楽器音色設定 | General MIDIプログラム0（ピアノ） |
| 元のベース音源との一致 | 未検証 |

音域で抽出しただけなので、**557音がすべて正しいベースラインである保証はない**。このMIDIには高音の混入や複数同時発音があり、ベース以外の音、採譜AIの誤認識、オクターブ誤りなどを含む可能性がある。まず原曲の低音と照合して正しいベースパートに修正すること。音高の合わない音を安易に1〜2オクターブ下げて譜面の正解にしてはいけない。

## 次の譜面追加手順

同梱のPythonスクリプトは `mido` が必要。

```bash
python -m pip install mido
python midi_to_chart.py "新しい曲.mid" --output-dir "converted_new_song"
# MIDIをZIPに入れたまま渡してもよい：
python midi_to_chart.py "新しい曲.zip" --output-dir "converted_new_song"
```

その後、生成された2つのJSONをゲームにインポートし、原曲の音源とタイミングを調整し、運指と奏法を手動確認する。
