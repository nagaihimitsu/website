## 保護するキメと休符

原本の14区間K01〜K14を保持し、21組の反復P01〜P21と、休止後の復帰・フィル終端・音域の切り返し16音A01〜A16を登録した。37件の定義は [kime-map.json](../src/room/charts/final-hit/kime-map.json) が正本。各キメは識別ID、区間ID、元ID、絶対時刻、代表する元音のID、保護フラグ、必要難易度、入力を空ける前後範囲を持つ。

- **23〜27秒（K06）**：EASYはP01／P03／P05、NORMAL／HARDはP01〜P06。
- **30〜34秒（K08）**：EASYはP07／P09／P11、NORMAL／HARDはP07〜P12。
- **34〜37秒（K09）「ポパッ、ポパッ」**：EASYは34.189583／35.071875／35.920833秒の3回。NORMAL／HARDは34.189583／34.631250／35.071875／35.502083／35.920833／36.362500秒の6回。
- **52〜55秒付近（K13）**：全難易度で52.208333／53.496875／55.321875秒の3回。
- 冒頭、復帰、その他のフィル・アクセント、終止も16音を全難易度で保護する。

高速なD→Eの2音は、**2音目のEアクセントを1回のスラップ**で演奏する。70〜117ms間隔の2入力は要求しない。原曲ミックスを変更していないため元の2音は両方聞こえる。EASYで省略する反復の場所にも通常音を差し込まない。

低域休止R01〜R06（2.47〜2.79、3.55〜3.85、5.89〜6.21、6.83〜7.28、16.17〜16.92、17.88〜18.32秒）も入力休符として保護する。通常ノーツの侵入と、保持の横断を拒否する。これらの推定ステムの35〜250Hzエネルギーは前後の約0.08〜0.79%。楽器の完全な無音を保証する値ではない。

## 元データとの照合と未確定情報

追加の`最終のヒット.mid`を既存コンバーターで読み、**全648イベントが既存JSONと完全一致**することを確認した。添付JSON・CSV・MIDIは `charts/final-hit/kime/` に元のバイト列で保存し、SHA-256を記録する。648音の正本と557音の候補JSONは変更しない。

提供JSONの`intraPairDelayMs`は約8〜12msだが、絶対時刻差は約70〜117msだった。正本MIDIの時刻から再計算し、元の値も証跡に残した。分析用MP3の60.048秒と配信音源の60.0135秒の差はパディングとして扱い、時刻を拡縮しない。MIDIメタ値120 BPMと音源の約140 BPMも区別し、どちらの拍にもノーツを量子化しない。オフセットは0秒を維持する。

既存KUIELab推定ベースステムと原音ミックスの両方について、各ペアの元音高・1〜2オクターブ下の周波数帯を比較した。反復後半P15〜P18は推定ステムで弱いが、提供分析とユーザー指定の反復を優先して保護し、従来の音量・音域フィルターで削除しない。

反復の元MIDI E3（52）は現行指板の範囲外なので、ゲームではE2（40）へ明示的に1オクターブ下げる。`sourceMidi:52`と`pitchMapping:octave-compatible-accent`を保存する。これは指板に合わせた編曲であり、元ベースの音高・楽器やスラップ奏法を確定したものではない。その他の通常候補は元音高を維持する。音高・運指・奏法・音源同期の確認フラグはfalse。耳で正確に採譜したとは扱わない。

## 制作・編集・検証

`scripts/prepare-final-hit-kime.py` が提供分析とMIDIを照合し、保護定義と解析証跡を生成する。制作専用のnumpy／scipy／soundfile／mido環境で実行する。通常のnpmテスト・ビルドにはPythonやFFmpegは不要。

```bash
python3 scripts/prepare-final-hit-kime.py --stem /path/estimated-bass.wav --mix '/path/最終のヒット.wav'
npx tsx scripts/arrange-final-hit.ts
npm run validate:final-hit
```

`scripts/arrange-final-hit.ts`は各難易度の保護キメを最初に配置する。その間の許された領域だけ、原音支持・オンセット・運指移動を評価する動的計画法で通常フレーズを追加する。HARDの通常候補からNORMAL、さらにEASYを選ぶ。全曲を一律に間引く方式ではない。キメ同士が運指条件を満たさなければ生成を失敗させ、無条件に消さない。

独立した`easy.json`／`normal.json`／`hard.json`がゲームの正本。各音に原ID・MIDI・時刻・位置・奏法を保存し、保護音には`kimeId`／`kimeGroupId`／`protected`／`sourceMidi`／`pitchMapping`も持たせる。`finalHitTrack.ts`は許可されたキメだけ音域変換を読み込み、`finalHitKime.ts`が欠落・重複・時刻変更・奏法変更・保護解除・休符侵入を検出する。原本、キメ定義、3譜面の整合性を変更後に必ず検査する。通常音の運指・奏法・除外パッチは従来通り。保護キメの除外パッチは明示的なエラーにする。

タイムラインと指板に同じ`data-kime-id`を出し、同一イベントであることを検査する。表示は既存の音高カラー・スラップ形状を再利用し、専用時計・採点・連打モードは作らない。

自動検証は3難易度の全曲入力、上下フリック、1入力1発音、音源原速、キメ位置・チャージ同期、正しい入力音高、SSリザルト、375／390／430pxを対象とする。実機iOSの指の感触と、人による全曲の聴音確定は未実施。具体的な今回の実行結果は [検証記録](VALIDATION.md) を参照。
