## 原本と音源照合

既存の`separate-garden-bass.py`と同じKUIELab MDX bassモデルをCPUで実行し、提供WAVから**推定**ベースステムを制作時だけ抽出した。外部サービスへの音声送信はない。推定ステムと残差の和は原音と最大2.98e-8差で、48kHz・2,880,648フレームを保持する。モデルは既存ライセンス・SHA検証を再利用し、サイトには追加のモデル・ステム・Python依存を配信しない。ゲームで再生するMP3も変更していない。

## 制作と検証の方法

推定ステムの反復音型と密度変化を参照し、導入のE/B応答、C/G、B/F#、Eへの戻り、Gの変奏、C/Bのアクセント、入力を休ませる間奏、D/Eの終止という区間を設定した。区間名も制作上の推定。音高支持・低域オンセット・途切れすぎない配置を評価し、移動時間を満たす経路を動的計画法で選ぶ。HARDを先に作り、その採用音からNORMAL、さらにEASYを選ぶ。一定間隔での機械的削除ではない。

スラップは推定ベースの立ち上がりの明るさと低域オンセットを使って各区間のアクセントを優先し、長さも考慮してゲーム用に割り当てた。MIDIの音高・velocityだけでは決めず、実演奏の奏法を耳で確定したとは扱わない。全ノーツを一律にスラップへ変換しない。

任意の1秒間を移動する窓で密度を検査する。最小間隔は0.55／0.36／0.26秒。さらに移動距離`弦差×1.4 + フレット差×0.7`の2.5超過分について0.15／0.075／0.045秒ずつ余裕を加え、距離3超のスラップ後は60msを追加する。保持後は160ms以上の解除時間も要求する。配置は近い同音位置も考慮する。[全検証値](../src/room/charts/final-hit/06_gameplay_validation.json)。

### 再現・編集

```bash
# オフライン解析用の任意環境。通常のnpmビルドには不要。
python3 scripts/separate-garden-bass.py '/path/最終のヒット.wav' --model /path/kuielab_a_bass.onnx --output-dir /tmp/final-hit-stems-new
python3 scripts/analyze-final-hit.py --mix '/path/最終のヒット.wav' --stem /tmp/final-hit-stems-new/bass.wav --metadata /tmp/final-hit-stems-new/metadata.json --output docs/analysis/final-hit-audio.json
npx tsx scripts/arrange-final-hit.ts
npm run validate:final-hit
```

解析はnumpy／scipy／FFmpeg、分離は既存ドキュメントのonnxruntime／soundfileを使用する。制作環境の`/tmp`へ導入し、npm依存や本番ビルドには追加していない。

独立した`easy.json`／`normal.json`／`hard.json`がプレイ譜面。曲ID、難易度、ノーツID、元ID、原時刻、MIDI、位置、奏法と任意の終端情報を保存する。原本JSONは編集しない。採用済みIDに対する`overrides.json`の運指・奏法・除外は引き続き適用する。未採用の音を追加する場合は各譜面を編集し、密度・移動検査も満たす必要がある。

## ジェスチャーと持続音

`bassGesture.ts`の主方向比を1.6に統一。縦フリックは上下共通、250ms以内・0.09px/ms以上。距離はセル高さの42%（18〜32px）、横移動は列間隔の24%（10〜20px）。横移動は同じ弦の範囲内に限り、行境界にはセル高さの18%（4〜10px）の揺れを許容する。45度付近は保留し、確定したSLAP／SLIDEを他奏法へ変更しない。開始位置・期待奏法・実ジェスチャー・速度は指別に管理する。

元の持続ループ（0.39〜0.55秒）には振幅差約0.121の継ぎ目と、160msごとの減衰があった。繰り返しnoteOnを呼ぶ実装ではなかった。`bassSustain.ts`で既存G1録音の最初のアタックを維持し、80msの滑らかな接続で、録音から抽出した12倍音の位相・振幅が安定した4周期の持続部へ移る。実MP3・24kHzの継ぎ目は約0.00150へ縮小した。1つのBufferSourceで保持し、スライドは同じ音声の再生率を補間する。解除は25ms、キャンセル・ポーズ・保持判定失効でも停止する。描画更新で再発音しない。

制作済みの持続バッファは曲の準備中に作り、入力直後の発音を遅らせない。原曲ミックスに元から含まれるベースのフレーズは引き続き聞こえるが、入力サンプラーの周期的再アタックや、直接入力に既存の連続ゲートを重ねる処理はない。
