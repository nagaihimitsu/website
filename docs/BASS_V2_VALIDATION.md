## 結果

- `npm test -- --reporter=dot`: 21ファイル・249件成功。
- `npx tsc -b`: 成功。終了時の入力解放を含む最終変更後も単体249件・ビルド・MIDI入力から結果／再演奏までのブラウザ確認が成功。
- `npm run build`: データ検証、ライセンス生成、型検査、Viteビルド成功。既存の大きいチャンクの警告は継続。
- Playwright全42件を実行: 初回36件成功、6件失敗。失敗の内訳と比較は下表を参照。

| ケース | 初回 | 変更前HEADを別ディレクトリで比較（外側タイムアウト120秒） |
|---|---|---|
| 新規の音源失敗・再試行 | 開発サーバーのMP3モジュール読込まで503にしていたテスト設定の不備 | 音声fetchだけを遮断するようテストを修正。機能の期待は維持 |
| 3倍以上のピンチ | 3倍を期待して1倍のまま | 同じ失敗を再現 |
| 360pxで記録画面から部屋へ戻る | room-homeが見つからない | 同じ失敗を再現 |
| Instagramリンク／360度見回し／パンチ | 45秒の外側タイムアウト | 3件とも成功（約1分かかるケースあり） |

比較元はGit HEADを `/tmp/bass-original` に展開したコード。ViteとPlaywrightのポート・キャッシュ出力先のみ変更し、機能コード・既存アサーションは変更していない。上記2件の既存失敗へ無関係な修正を混ぜていない。改修後も外側タイムアウトを120秒にして3件を再実行し、すべて成功した。修正した音源失敗テストも成功（4件の再実行は全件成功）。ユニークな42ケースのうち40件は成功を確認でき、変更前から再現する2件は未解消。新規のベースE2Eは8件すべて成功している。既存テストの期待値や既定タイムアウトは変更していない。

全体E2Eがすべて成功したとは扱わない。残るピンチと記録画面からの復帰は今回の指板UIの外側の既存問題として残す。

変更前の単体テストは222件成功、写真の書き出し1件がサンドボックスのIPC制限（listen EPERM）で失敗した。必要なネットワーク権限を付けた実行では、この既存テストも成功した。写真処理へのコード変更はない。

## 確認範囲と残る実機確認

iOS Safariの実機での聴感・端末遅延・アドレスバー・ノッチの確認は未実施。既存のユーザー操作内の音声初期化、webkitAudioContext、音声中断時の再開、safe-area、安定したsvhによる指板高を使用している。

録音からのサンプラーは元音源の音色を使用するが、短いループの継ぎ目とピッチ変更の音質は端末スピーカー／ヘッドホンで最終調整の余地がある。元の音源に専用スラップ録音がないため、スラップは同じサンプルの強いアタックで表現する。自由演奏モード、別曲、ランキング／スコア保存は追加していない。


## GitHub Pages公開準備（同日）

公開を依頼されたため、既定の全件検査を保ったまま、公開を止める既存E2Eの入力・待機方法を修正した。

- ピンチ拡大テストは起点のy=450が中央のコレクション操作ラベルと重なり、canvasへ2本の指が届いていなかった。起点をラベルより上へ移し、開始後に実際のdata-pinching=trueも検証するようにした。3倍・6倍・逆方向・キャンセル・復帰・主人公の不透明度という検査内容は維持し、テスト成功を確認した。
- 360px画面の遷移は、動的に読み込まれるroom-homeの出現も既存の部屋初期化と同じ30秒の範囲で待つようにした。表示とスクロールの検査は維持し、テスト成功を確認した。
- ソフトウェアWebGLで一連のポインター操作に約1分かかるため、外側のテスト実行時間を120秒へ変更した。要素の状態や数値のアサーションは変更していない。

上記は先の「2件未解消」というUI改修時点の記録を更新するもの。Pagesの既存ワークフローはmainへの反映時に全テストを実行し、成功後に公開する構成を維持する。

- `/website/` の本番ビルド検査では、実際に「日本」を登録済みのデータを「空でなければ失敗」とする古い保護アサーションが残っていた。テスト開始前後で公開データ2ファイルの全内容が同一であることを検証する方法へ修正し、実績の非破壊という意図を維持した。

修正後の `npm run test:subpath` は成功し、`/website/` 配下の3D表示、TXT、写真、ハッシュURL再読込と元データの維持を確認した。
