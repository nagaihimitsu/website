# ベース演奏のリザルト

## 表示と操作

曲の終了後に、アイボリー色のカードで曲名、難易度、SS／S／A／B／C／D、達成率（小数2桁）、Excellent／Great／Good／Bad／Missの件数、最大コンボを表示する。既存のSCOREも小さく残す。0.18秒のフェードのみでボタンを待たせず、動きを減らす設定ではフェードを無効にする。

- **続ける**：既存の選曲画面へ戻る。曲・難易度・手動オフセットを保持し、スコア・判定・コンボ・結果を初期化する。別曲も選択可能。
- **やめる**：既存の「ベースを置く」操作で3Dホームへ戻る。現在のサイトには専用ゲームタイトル画面がないため、演奏前のホームを終了先として再利用する。すぐ自動で再取得しない既存の離脱待ちも維持する。

連打は表示側のrefとエンジンのphaseガードで防止する。結果表示時は指板・選曲・ポーズを描画せず、演奏入力を受け付けない。ダイアログへフォーカスし、Tabを2ボタン内で循環させ、「続ける」の後は曲選択へフォーカスを戻す。Escapeは終了、結果画面でのEnter／Spaceは直接再演奏せず選曲へ戻る。

## 計算

`src/room/bassResult.ts`の`BASS_RESULT_CONFIG`が係数と閾値の正本。`calculateBassResult`と`bassResultRank`は通信・保存・UIを持たない純粋関数。

| 判定 | 係数 |
|---|---:|
| Excellent（既存の内部perfect） | 1.0 |
| Great | 0.8 |
| Good | 0.5 |
| Bad | 0.2 |
| Miss | 0.0 |

達成率は`(Excellent + Great × 0.8 + Good × 0.5 + Bad × 0.2) / 総判定数 × 100`。分母にはMissを含め、空譜面は0%。整数の判定数に係数×100を掛けてから割り、境界での余分な浮動小数点誤差を抑える。

SSは98%以上、Sは90%以上、Aは80%以上、Bは70%以上、Cは60%以上、それ未満はD。表示だけを`toFixed(2)`で丸め、ランクは未丸めの値を使う。97.995%は表示98.00%でもS。

SCOREの既存の1000／850／650／250／0点と空振り減点、演奏中のaccuracy診断属性は変更しない。達成率の係数とは別のルールとして保持する。空振りを譜面ノーツとして加算しない。開発用シークで対象外にしたskippedも従来どおり分母から除く。

## 終了と責務

`bassGame.ts`の共通終了処理で残るpending／holding／slidingをMiss確定してから、最終状態を1回だけ集計する。開始通知やフリック通知を直接数えず、ノーツごとの最終判定を数えるため、ロング・スラップ・スライドも各1件となる。既存の`maxCombo`をコピーし、現在コンボが切れても最大値は残す。結果本体と判定数をfreezeし、後続フレーム・解除・キャンセルで再集計しない。

`RoomEngine.continueBass`は音声、入力、開始待ち、時刻アンカーを解放して選曲へ戻す。終了は既存の`putDownBass`、音声停止は既存の`bassAudio.stop/sync`を使用する。`BassGameHUD.tsx`は確定結果を描画し、スコアを変更しない。曲・3D・音源・保存キー・ハッシュURL・依存は変更していない。
