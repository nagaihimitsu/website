# テラスのベース演奏 Ver.2

部屋のテラスでベースに3秒間近づくと、既存の主人公が楽器を持ちます。React／TypeScript／Three.jsと既存の音楽素材を利用し、スマートフォン縦画面で直接指板を弾くゲームです。

## 遊び方

1. 「曲」でGarden-Party Grooveまたは最終のヒットを選び、「演奏する」を押します。既存曲はEASY／NORMAL／HARD、新曲は0〜5Fの315音を対象にしたMIDI仮譜面です。新曲の同期・運指・奏法は未確認のまま区別し、準備画面で譜面のタイミングを調整できます。スコア保存は追加していません。
2. 常設タイムラインの音名が左の縦線に来たら、同じ音高の指板ボタンを押します。通常音はタップ、帯付きは終端まで保持して離す、↑付きは上へ素早くフリックします。
3. 指板の外周と内部充填は同じ進行率を使い、100%が発音時刻です。保持中は終端へ向けたゲージになります。
4. ポーズは上部のⅡ、再開は既存メニューの「部屋に戻る」。中断時は音声と入力を解放し、楽曲時刻を保持します。保持中だった音は再開後に同じ音高を押して拾い直せます（終了判定は最大Good）。「置く」で部屋の移動へ戻ります。

指板は上からG2／D2／A1／E1の4弦、左から0F〜5Fの24ボタンです。MIDI 28〜39は青、40〜48は赤。音名の小数字はオクターブです。A1、D2、G2の重複位置はどちらも正解になり、異なるオクターブは別音として判定します。

PCでは指板ボタンにフォーカスしてSpace／Enterで押し、キーを離して終了します。Shift併用で上フリックを代替できます。従来の7／8／9／0の弦専用ショートカットは廃止しました。

## 譜面・時計・判定

`gardenTrack.ts` の実測アタックと音高から既存の難易度別選択を維持します。旧弦番号は上からG／D／A／E、フレットは実際の半音数であり、MIDIは開放弦＋フレットで確定できます。旧phrase.modeのholdは自動押弦ガイドなので、新しい長押しには直接変換しません。NORMAL／HARDの通常音で、次の発音まで1.1秒以上ある箇所に、最大0.8秒のゲーム用保持時間を追加しています。録音の発音時刻と音高は変えません。

各音符は固有ID、time、midi、kind（tap／hold／slap）、任意のendTimeと判定状態を持ちます。描画2種類は同じスナップショットのnotesとelapsed（カウント中は負の時刻）だけを参照します。音符位置は `judgeX + (time - elapsed) * pixelsPerSecond`。表示設定は `bassVisuals.ts` の `BASS_VISUAL_CONFIG`（予告1.2秒、200px/秒、最大2.4秒先）です。密集時は小さいマーカーを上下交互に配置し、時間に対応するX間隔は維持します。休符も表示領域は変わりません。

元の外側の判定幅180ms、最大1000点、Good650点、空振り250点減点を維持し、その範囲内を5段階へ細分化しました。

| 判定 | 前後の時間差 | 点数 | コンボ |
|---|---:|---:|---|
| Excellent（内部perfect） | 45ms以下 | 1000 | 継続 |
| Great | 85ms以下 | 850 | 継続 |
| Good | 140ms以下 | 650 | 継続 |
| Bad | 180ms以下 | 250 | 解除 |
| Miss | 判定なし・ホールド早離し・フリック不成立 | 0 | 解除 |

ホールドは開始と解放の悪い方の判定を終了時に1回加算します。終了後180msを超えて保持した場合はBadで確定します。入力はMIDI音高と最も近い未判定ノーツを照合し、1入力が消費するイベントは最大1件。スラップは開始時刻で予約し、250ms以内・24px以上・主に上方向の移動で確定します。別ノーツを追加で消費しません。

RoomEngineがWeb Audioのサンプル時計からゲームを進行させ、入力時には描画フレームとは独立して時刻を取得します。イベントのtimeStampを同じ時計へ換算して判定し、タイムライン／チャージ側は判定を進行させません。

## 音声と入力

伴奏は既存の録音を原速で再生します。直接入力の音は、分離済みベース録音のG1アタックを基準に `2 ** ((midi - 31) / 12)` のplaybackRateで28〜48へ変更します。保持はアタック後の短い区間をループし、解放時に音量を滑らかに下げます。素材再生成や音源追加はありません。元のベース録音の連続ゲートは直接入力の音には重ねません。

発音は判定から独立し、誤入力も押した音高で鳴ります。スラップ専用録音が元の実装にないため、該当ノーツの接触時に強めのアタックで1回鳴らし、フリック成立時は再発音しません。専用奏法録音の音質そのものは再現していません。

指ごとに開始ボタン・MIDI・開始時刻・楽曲時刻・移動差分・経過時間・解放時刻を保持します。Pointer Captureで起点を固定し、通過したボタンは鳴りません。同じボタンへのマルチタッチ、連打にも別IDを割り当てます。ブラウザのスクロール・選択は指板で抑止します。キャンセル、画面非表示、メニュー、終了で音声と接触状態を解放します。iOS向けには既存のユーザー操作内でのAudioContext生成／resumeと音声再開ボタンを維持します。

## 主人公と背景

ベースは提供された三面図と、その後の演奏姿の見本を基にした立体モデルです。細身で左右非対称の赤茶の木製ボディに、ボディ内部まで伸びる長い指板、22フレット、連続した白いピックガード、3個の丸いノブ、楕円形のペグを配置。裏側には丸いメイプルのネック、4本ねじのネックプレート、ペグの歯車も造形しています。4本の弦・フレット・サドル・指先は同じ実寸法を参照し、12フレットが弦長の半分になる間隔です。

演奏時はネックを耳の高さまで立て、奏者を斜め前から見せます。短く丸い動物の指で支え、平たいチャコール色のストラップが肩を通ってホーン前面とボディ下端の金具につながります。待機中は9フレット付近で支え、曲が始まると実際の譜面のフレットへ移動します。ピッキングは指板の終端付近、スラップは手全体と短い親指で同じ付近を叩きます。シールドは白いピックガード下端の出力ジャックにL字プラグで接続し、楽器の動きに合わせてアンプまでのたるみが変わります。スタンド上と保持中の楽器の倍率は共通です。

演奏中も肩の付け根を胴体に固定し、リュックの肩紐の下から太い上腕が出る形にしています。弾く側は肘を内側・前方へ畳み、短い前腕を楽器の縁に沿わせます。実メッシュの肩から袖口までを測り、通常時100に対する待機時の長さを175.8から141.8へ短縮しました。押さえる側の待機142.0とほぼ同じです。演奏中は弦とスラップの位置に応じて141.3〜156.8となり、固定長の骨格ではありません。上腕の厚みを保ち、袖口は掌の向きに沿わせています。リュックの肩紐も肩・脇・バッグ下側の取付部をつなぎます。小さな掌に短い指を丸め、指の断面は曲がり目でねじれない基準を使い、袖の陰影も曲げた実形状から更新します。


## 変更する場所

| ファイル | 所有する状態・責務 |
|---|---|
| `bassFretboard.ts` | チューニング、24位置、MIDIから音名・色・周波数を生成 |
| `bassGame.ts` | 既存譜面変換、進行、入力予約、判定、スコア、コンボ |
| `bassInput.ts` | 指ごとの起点・移動・フリック成立・終了 |
| `bassVisuals.ts` | タイムライン位置とチャージの純粋計算・表示設定 |
| `BassGameHUD.tsx` / `bassGame.css` | 上部HUD、常設タイムライン、24ボタン、結果・難易度 |
| `bassAudio.ts` | 録音の準備と共通時計、MIDIサンプラー、音声解放 |
| `roomEngine.ts` | 上記を接続し、既存3Dと入力時刻を更新 |
| `bassGameStore.ts` | 演奏UIだけに30fpsでスナップショットを通知 |

旧プログラム向けの `pluck` APIは既存テストとの互換用に残っていますが、新UIは `inputBass` を使用します。3D内部状態をReactへ移していません。音源の更新手順は [ROOM_BASS_AUDIO.md](ROOM_BASS_AUDIO.md)、今回の確認は [BASS_V2_VALIDATION.md](BASS_V2_VALIDATION.md) を参照してください。

新曲の原本、範囲外音の記録、オフセット、運指・奏法の保存と修正手順は [FINAL_HIT_IMPORT.md](FINAL_HIT_IMPORT.md) を参照してください。
